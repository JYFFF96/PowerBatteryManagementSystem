# PowerBatteryManagementSystem — Qt Widgets 深色监控版

基于用户参考截图重新设计的 **Qt 6 + Widgets + C++17 + qmake (.pro)** 动力电池/BMS 调试客户端。

## 界面

主界面采用深色工业监控风格、左侧导航和顶部 CAN 控制栏，包含九个页面：

1. 实时总览：总压、电流原始值、SOC、SOH、充放电状态、单体压差、走势图和分布图
2. 单体电压：1～192 节电压监测、极值/平均值/压差、柱状图、CSV 导出
3. 温度监控：1～64 路温感、极值/平均值/温差、柱状图
4. 故障诊断：TKB 协议 13 种故障位、0～3 级状态
5. 波形记录：总压、电流原始值、SOC 和电压极值，暂停/清除
6. 报文监视：实时 RX CAN 数据及解析名称
7. 数据记录：录制缓冲、停止、导出 CSV
8. CAN 下发：**只展示协议能力，发送禁用**（精简版未提供 ECU→BMS 完整指令格式）
9. 系统设置：本地阈值、模拟规模、录制缓冲数量，保存/恢复默认

## 构建

Qt Creator 打开 `PowerBatteryManagementSystem.pro`，选择 **Qt 6.7.3 / MSVC 2022 64-bit** Kit，运行 qmake 并构建。
CMake 项目文件作为可选方式同步维护。

Windows 需要将本人 `mmWaveRadar/libs/ControlCAN.dll` 复制至生成的 EXE 同目录，确保 DLL 位数与编译器一致并已安装硬件驱动。程序通过 `QLibrary` 读取 VCI_* 导出函数，不依赖厂商 .lib 静态导入库。

适配器仅显示 USBCAN-II（驱动设备类型 4）；设备编号可选 **0/1/2**（默认 0），界面通道 **CAN 1/CAN 2**（默认 CAN 1，底层索引分别为 0/1），波特率 **250/500 kbps**（默认 250）。实际 TKB BMS V1.1 协议规定 250 kbps，只有设备确实改为 500 kbps 才应切换。扩展帧（29-bit），8 字节。\n\n连接成功后按钮为红色“断开连接”、状态绿点“已连接”；断开时按钮为蓝色“开始连接”、状态红点“已断开”。启动模拟按钮保留。

可点击“启动模拟”查看有意义的示例数据；连接真实 CAN 时停止模拟并清空状态，只显示实际收到的数据。

## 数据协议与安全说明

- TKB BMS V1.1 精简版定义：0x02018100～0x02058100、0x02108100～0x023F8100、0x02468100～0x024D8100
- 温度 FID 范围在文档的标题和表格中存在矛盾，暂按标题的 0x46～0x4D 解析，须实机核对。
- 当前约定将电流 Byte 1～2 按无符号大端 16 位解析，乘以 0.1 A，界面显示非负幅值；充电/放电方向单独由 Byte 3 确定。精简协议没有明确负数编码，后续需用真实设备报文验证，不以此值计算准确充放电功率。
- 预计续航显示位置保留为 `-- km`，等待后续能耗/续航模型；精简协议未提供车辆续航和循环次数。\n- `0x02028100` 的“最严重故障代码”目前没有配套代码表，暂不解读；已有的 `0x02058100` 故障状态位仍可解析。\n- 本地阈值只是上位机视觉提示，**不修改 BMS 保护设置**。
- CAN 下发控制功能默认不实现：目前没有完整厂商下发协议，避免错误控制电池系统。
- 目前尚未完成实际 Windows Qt/MSVC 编译和硬件联调验证。

## 结构

`src/dashboardwindow.*`：全部界面、绘图、模拟/实时数据刷新、导出；`src/bmsprotocol.*`：TKB 协议解析；`src/canadapter.*`：Windows ControlCAN 接收线程。

下一阶段可将单页 Widget 拆分为独立类，补充接收超时提示、真实电流符号、原始 CAN 精确日志时序与完整厂商指令表。

## QCustomPlot 曲线与性能（本次更新）

- 从本人的 `mmWaveRadar` 仓库复用 **QCustomPlot 2.1.1** 源码（`thirdparty/qcustomplot/`），保留其 GPL 许可声明；.pro 和 CMake 均已加入 Qt PrintSupport 与源文件。
- 实时总览的 3 张趋势图按 **1:1:1** 等宽排列；所有 8 张图表都采用 QCustomPlot，单体与温度分布继续使用柱状图。
- 趋势曲线 X 轴使用 `HH:mm:ss` 本地时间。按时间戳保留最近 **3600 秒**，过期样本从曲线缓冲和 QCustomPlot 内部数据中删除，而不是按固定 160 条截断。
- CAN 接收继续运行于独立的 QThread；UI 主线程只处理已接收的数据批次，图表更新最多约每 500ms 一次，监视/录制表格也改为定时、限量刷新以减少界面卡顿。
- 建议先在无设备情况下启动模拟并运行至少 1 小时，观察曲线的时间轴与内存使用。Windows Qt 6 / MSVC 2022 实机编译和高负载联调仍需本地验证。

## 24 路实时分布图（2026-11-27）

- 实时总览下方的单体电压和温度分布图采用 1:1 等宽卡片，均按 24 个槽位显示；未接收到的数据保持空白，不用模拟数值代替。
- 标题、最低/最高/正常颜色图例、本地过压/欠压（或高低温）阈值备注在同一行；备注随系统设置的本地阈值变化。
- X 轴在每个槽位的柱子下方显示实际测量值：单体电压保留两位小数（V），温度显示整数（°C），未收到的槽位显示 `--`。柱状图 Y 轴仍展示对应的物理数值。
- 24 节电池和 24 路温度是当前软件的界面/演示约定；底层协议解析仍支持协议定义的最多 192 节单体、64 路温度，以免丢失原始信息。温度的实际硬件路数最终须按实机报文确认。
